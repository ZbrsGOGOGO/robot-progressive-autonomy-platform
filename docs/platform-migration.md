# 接入与迁移

先为控制端、本体和工位分配稳定 ID，再将输入、设备状态和录制接入 SDK。控制端发送统一输入帧，运行时管理会话与控制权，机器人本地控制器负责闭环执行和物理安全。已部署的相机、设备驱动和媒体可作为独立服务接入。

## 接口对应

| 能力 | 公共 SDK | 兼容层与集成要点 |
| --- | --- | --- |
| 控制端和机器人登记 | `register_controller`、`register_robot` 和 `GET /v1/status` | 兼容服务在 loopback 提供 `/api/register`、`/api/poll`、`/api/report`。注册与上报供观察，轮询返回空命令列表。 |
| 工位和控制权 | `POST /v1/sessions` 及会话的 `arm`、`hold`、`resume`、`close` | 活动会话对工位、控制端和本体互斥。进程状态和注册成功仅供诊断。 |
| 控制端输入 | `POST /v1/sessions/{id}/input` 和统一输入帧 `rpa.input.v1` | 可选 TrackingData 转换器负责字段映射。坐标、时钟转换和真机输入时限由集成方验证。 |
| 健康和故障 | `GET /v1/robots/{id}/health` | `LegacyRobotAdapter` 提供旧设备注册和状态观察。接入真实驱动时映射反馈新鲜度、模式、告警和控制器故障。 |
| 录制 | 会话的 `record/start`、`record/mark`、`record/stop` | `LegacyRecorderClient` 使用本机 Recorder 的 `/rec/*` 接口，默认只读。历史 Episode 以支持的 v1 目录格式离线导入。 |
| 关键帧 | `POST /v1/sessions/{id}/action` 支持预览和模拟终态 | 真机动作走经独立验收的本地控制链。 |
| 观测和媒体 | 机器人状态与观测接口，按相机角色采集图像 | 实时视频、语音和设备专用遥测通过独立通道集成。 |

会话操作以 `/v1/sessions/{id}/` 为路径前缀。把业务任务名、阶段标记和任务结果逐项映射到 `task`、`label` 和 `outcome`。旧协议、Recorder 客户端及 Pico Unity XR 示例见[设备与录制器接入](integrations.md)。

## 接入顺序

1. 用模拟器验证工位分配、授权、中立首帧、超时保持、显式恢复和录制提交。检查会话回执、原始事件和质量清单，并记录所用版本和配置。
2. 用脱敏的旧设备日志验证 TrackingData 解码。核对序号、采样时间、单位和坐标。由可信的输入源独立提供追踪有效性。
3. 在同机通过兼容服务验证设备登记、心跳和状态上报。按[离线导入格式](data.md#离线导入兼容-v1-episode)验证已提交的旧 Episode。旧 Recorder 写操作仅由明确拥有本次录制的客户端发起。
4. 为 ROS2 或厂商控制器实现 `RobotAdapter`。验证反馈新鲜度、运动模式、坐标、关节限位、本机看门狗和停止确认。先做回放、影子输出和单部件测试，再按本体的验收流程启用实机，保留物理急停和回退入口。

参考服务在进程内管理设备与会话，令牌适用于受控联调。生产接入需在部署层落实设备和操作员身份、工位授权、传输加密、审计及重启后的状态恢复。实体机器人失联后的停止和物理急停由本地设备控制器执行。
